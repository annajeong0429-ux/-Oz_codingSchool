# 🏥 폐렴 판독 백오피스 팀 규칙

## 팀 소개
흉부 X-Ray 폐렴 판독 모델을 활용한 폐렴 환자 관리 백오피스 구축 프로젝트

---

## ✅ 기본 규칙

### 1. 코어 타임
- 매일 저녁 3시 30분 ~ 6시 40분 Zep에 모여서 진행하기
- 불참 시 최소 1시간 전에 팀원들에게 공유하기

### 2. 1일 1커밋
- 자신의 브랜치에서 하루에 최소 1커밋씩 작업 후 원격 레포지토리에 푸시하기
- 커밋 메시지는 명확하게 작성하기

### 3. 존중하는 소통
- 무슨 일이 있어도 감정은 절제하고 부드러운 언어로 대화하기
- 쿠션어 사용하기 (예: "혹시 가능하다면...", "제 생각엔...")
- 화가 나면 잠깐 바람 쐬고 오기

### 4. 적극적인 회의 참여
- 팀 회의 시 마이크는 항상 켜기
- 눈치 보지 않고 적극적으로 의사 표현하기
- 모르는 것은 바로바로 질문하기

### 5. 진행 상황 공유
- 작업 시작/완료 시 팀 채팅방에 공유하기
- 막히는 부분은 혼자 2시간 이상 고민하지 말고 팀원에게 공유하기

## 🌿 Git & GitHub Rules

### 브랜치 전략
```
main        ← 배포 가능한 안정 버전 (직접 push 금지)
dev         ← 개발 통합 브랜치
feature/*   ← 기능 개발 브랜치 (예: feature/login-api)
hotfix/*    ← 긴급 버그 수정
```

### 커밋 메시지 규칙
```
feat:     새로운 기능 추가
fix:      버그 수정
docs:     문서 수정
style:    코드 포맷 변경 (기능 변경 없음)
refactor: 코드 리팩토링
test:     테스트 코드
chore:    빌드 설정, 패키지 수정
```

예시:
```
feat: 폐렴 판독 예측 API 엔드포인트 추가
fix: X-Ray 이미지 업로드 오류 수정
docs: API 명세서 업데이트
```

### PR(Pull Request) 규칙
- `main` 브랜치에는 직접 push 금지, 반드시 PR을 통해 merge
- PR 생성 시 변경 내용을 간단하게 작성하기
- 최소 1명 이상의 팀원 리뷰 후 merge
- PR 제목 형식: `[feat] 기능명` 또는 `[fix] 버그내용`

### 코드 리뷰 규칙
- 리뷰는 24시간 이내에 완료하기
- 코드 중심으로 리뷰하기 (사람 비판 금지)
- 이유를 남긴 코멘트 작성하기
