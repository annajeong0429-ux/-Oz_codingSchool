## 1. 각 디렉터리 역할

### app/core/
프로젝트 전체에서 공통으로 사용하는 핵심 설정 모음.
- `config.py` : 환경변수(.env) 읽어오는 설정
- `db/databases.py` : DB 연결 설정
- `db/models.py` : DB 테이블 구조 정의 (Base 클래스)

### app/models/
SQLAlchemy ORM 모델 작성하는 곳.
DB 테이블을 Python 클래스로 표현함.
- 예시: `patient.py` → patients 테이블 정의
```python
class Patient(Base):
    __tablename__ = "patients"
    id = Column(Integer, primary_key=True)
    name = Column(String)
```

### app/repositories/
DB에 직접 접근해서 CRUD(생성/조회/수정/삭제) 수행하는 곳.
- 비즈니스 로직 없이 오직 DB 조작만 담당
- 예시: `patient_repository.py` → 환자 조회, 추가, 삭제 쿼리 작성

### app/schemas/
API 요청/응답 데이터의 형식(타입)을 정의하는 곳.
- Pydantic 모델 사용
- 예시: `patient_schema.py`
```python
class PatientCreate(BaseModel):
    name: str
    age: int
```

### app/services/
비즈니스 로직(핵심 기능)을 처리하는 곳.
- repositories를 호출해서 데이터를 가져오고 가공함
- API와 DB 사이의 중간 다리 역할
- 예시: `patient_service.py` → 환자 등록 시 중복 체크 후 저장

### app/apis/
클라이언트(브라우저, 앱)의 요청을 받는 곳.
- FastAPI Router 등록
- 요청 받기 → service 호출 → 응답 반환
- 예시: `practice_apis.py` → GET /users, POST /users 등

## 2. 각 파일 역할

### app/main.py
FastAPI 서버의 시작점 (가게 문 여는 곳).
- FastAPI 앱 생성
- 라우터 등록
- 미들웨어 설정
```python
app = FastAPI()
app.include_router(user_router)
```

### app/core/config.py
`.env` 파일에서 환경변수를 읽어오는 설정 파일.
- DB 접속 정보, 비밀키 등 민감한 정보 관리
```python
class Settings(BaseSettings):
    DB_USER: str
    DB_PASSWORD: str
    DB_HOST: str
```

### pyproject.toml
프로젝트 패키지 의존성 및 설정 파일 (pip의 requirements.txt 역할).
- 필요한 라이브러리 목록과 버전 명시
- uv가 이 파일을 보고 패키지 설치함

### uv.lock
실제로 설치된 패키지의 정확한 버전을 기록한 파일.
- 팀원 모두가 똑같은 버전으로 설치되도록 보장
- 직접 수정 금지 (uv가 자동 관리)

## 3. app/core/db/databases.py - DB 연결 설정

```python
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine
from typing import AsyncGenerator
from app.core.config import settings

DATABASE_PREFIX = "mysql+asyncmy://"
DATABASE_URI = f"{settings.DB_USER}:{settings.DB_PASSWORD}@{settings.DB_HOST}/{settings.DB_NAME}"
DATABASE_URL = f"{DATABASE_PREFIX}{DATABASE_URI}"

# 비동기 엔진 생성
async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)

# 비동기 세션 팩토리 생성
AsyncSessionLocal = async_sessionmaker(bind=async_engine, autoflush=False)

# 모델 베이스 생성
Base = declarative_base()

# 세션 생성 함수
async def async_get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as db:
        yield db
```

**각 줄 설명:**
- `create_async_engine` : DB와 비동기로 연결하는 엔진 생성
- `AsyncSessionLocal` : DB 작업할 때 사용하는 세션(연결 통로)
- `Base` : 모든 모델이 상속받을 베이스 클래스
- `async_get_db` : API에서 DB 세션을 주입받을 때 사용하는 함수

## 4. SQLAlchemy 모델 작성 + Alembic 마이그레이션

### SQLAlchemy 모델 작성 (app/models/patient.py 예시)
```python
from sqlalchemy import Column, Integer, String
from app.core.db.databases import Base

class Patient(Base):
    __tablename__ = "patients"

    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(100), nullable=False)
    age = Column(Integer)
```

### Alembic 마이그레이션 순서
마이그레이션 = Python 모델 코드를 실제 DB 테이블로 반영하는 것

```bash
# 1. 변경사항 감지해서 마이그레이션 파일 자동 생성
alembic revision --autogenerate -m "변경내용 설명"

# 2. 생성된 마이그레이션을 DB에 실제 반영
alembic upgrade head

# 3. 현재 적용된 마이그레이션 확인
alembic current

# 4. 이전 버전으로 되돌리기
alembic downgrade -1
```

## 5. API 구현 흐름

```
클라이언트 요청 (브라우저/앱)
        ↓
   app/apis/         ← 요청 받기 (Router)
        ↓
   app/services/     ← 비즈니스 로직 처리
        ↓
   app/repositories/ ← DB CRUD 수행
        ↓
   app/models/       ← DB 테이블 구조
        ↓
   app/schemas/      ← 응답 데이터 형식으로 변환
        ↓
클라이언트 응답 반환
```

### 실제 예시 (환자 조회 API)
```
GET /patients/1 요청
    ↓
apis/patient_api.py : id=1 받아서 service 호출
    ↓
services/patient_service.py : 유효성 검사 후 repository 호출
    ↓
repositories/patient_repository.py : DB에서 id=1 환자 조회
    ↓
schemas/patient_schema.py : 조회 결과를 응답 형식으로 변환
    ↓
{"id": 1, "name": "홍길동", "age": 30} 응답 반환
```
